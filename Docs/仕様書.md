## 1. オプション機能の組み込み

### やりたいこと
仲間が作ってくれたオプション機能をゲームに追加する。

### 決まっていること
- **開ける場所**: タイトル画面とゲーム中（設定ボタン）の **両方**。設定内容は両方で **共有** する
- **項目**:
  - 音量設定（BGM 音量・SE 音量）
  - 画面表示（フルスクリーン／ウィンドウ）… 11番
  - 文字の速さ（遅い・普通・速い）… 15番
  - オートの待ち時間（短い・普通・長い）… 15番
  - スキップの種類（既読のみ／すべて）… 15番
  - セーブ・ロード（**ゲーム中に開いたときだけ**）… 8番
  - ゲーム終了
  - ゲームに戻る（オプション画面を閉じる）
- オプションの設定は **保存** し、ゲームを閉じても次回まで残す（セーブ枠とは別。どのセーブでも共通）

### 今の状態
- 作業用シーン `Scenes/WorkSpace/Work_MIYOSI/option/` にある（作成: ZM2GTBJI さん）
  - `optionbutton.cs`：オプション画面の開閉、ゲーム終了ボタン

- 本番シーン（Title / InGame）には置かれていない
- InGame には押しても何も起きない `Setting_Button`（設定ボタン）がある
- 音量の保存はまだできていない（起動するたびに 0.5 に戻る）

## 3. キーアイテム・情報の追加

### やりたいこと
キーアイテムや情報を追加する。

### 決まっていること
- **入手方法**（今のところ）:
  - 特定のセリフを聞いたとき
  - 聞き取り
  - スマホ会話
- **プロフィールは入手方法の対象外**。プロフィールは「プレイ中に得た情報の記録」と「キャラクターの設定」を見る場所
- 手に入れたキーアイテム・情報は、**プロフィール画面に書き込まれる** ようにする（今は一覧で見る画面はない）
  - **情報**: キャラに関係するものは **そのキャラのページ** に、キャラに関係しないものは **全体（その他）のページ** に書き込む
  - **キーアイテム**: プロフィール画面に **アイテムの項目** を作り、そこに書き込む
  - 例：「メリのアリバイ」→ メリのページ、「事件当日は雨だった」→ その他のページ、「現場の鍵」→ アイテムの項目
  - どのページに出すかは、6番の「フラグ一覧のシート」で指定する
- （予定）手に入れた情報は **2周目以降も引き継ぐ**。周回をまたいで集めた数が増えても見やすいように、資料画面の見せ方をデザイナーさんと相談中（デザインの依頼は `Docs/資料画面のデザイン相談.md`、プログラム側で作る動きは `Docs/資料画面の動き_プログラム側.md`）
- 情報の手に入れ方は「会話」と「ポイントで解禁」の2つ。**1つの情報はどちらか片方だけ**で手に入る（2026-10-17 決定）。フラグ一覧のシートに「解禁ポイント」の列を足し、空なら会話で手に入る情報、数字があればそのポイントで解禁する情報にする
- キーアイテムは**見るだけ**（プレイヤーが「使う」操作はない）。資料画面のアイテムのページには**絵**を出す（2026-10-17 決定。絵の素材はデザイナーさんに相談）

### 未定（後で一緒に決める）
- 具体的なキーアイテム・情報の一覧（名前・説明・入手条件）
- プロフィール画面の「その他」「アイテム」ページの見た目

## 4. 条件つきの会話の選択肢

### やりたいこと
特定の条件を満たしたときだけ、会話に選択肢を出せるようにする。

### 決まっていること
- 条件の例：
  - キャラクターから情報をもらった後だけ選べる選択肢
  - キーアイテムを持っているときだけ選べる選択肢
- **条件を満たしていないときは、選択肢そのものを表示しない**
- **選ぶと起きること**: 専用のセリフ、好感度の変化、新しい情報の入手、ルート分岐
- **出す場所**: 取調室の会話とスマホ会話の **両方**
- 選択肢は **各行動ごと** に用意する（例：対話のときだけ出る選択肢、拷問のときだけ出る選択肢）
- 行動回数は **行動と選択肢を合わせて1回**（「対話」を選んで1回使い、その中で選択肢を選んでも追加では使わない）
- スマホ会話でも同じく、**会話と選択肢を合わせて1回**。使うのは **スマホの「1日に聞ける回数」** で、取調室の行動回数（1日4回）は使わない

### 未定
- どの場面で選択肢を出すか
- ルート分岐の内容

### Excel の書き方（決定）: 「選択肢シート」
会話（セリフID）が終わった後に出す選択肢を、1行に1つ書きます。
- **条件を満たした選択肢だけ** を「順」の順番で出す（1つもなければ選択肢は出ない）
- 選択肢が出たら **必ずどれかを選ぶ**（選ぶまで後ろの画面は操作できない）
- 選んだ後の会話（次のセリフID）にも選択肢を書けば、**続けて選べる**（ルート分岐を何段でも作れる）
- 次のセリフIDが空欄なら、会話はそこで終わる
- 好感度の変化は会話の相手に対して。スマホ会話では好感度の条件・変化は使わない

| セリフID | 順 | 選択肢の文 | 必要フラグ | NGフラグ | 本人の好感度 | 他キャラの好感度 | 好感度の変化 | 獲得フラグ | AI化 | 次のセリフID |
|---|---|---|---|---|---|---|---|---|---|---|
| A_D3_対話_1 | 1 | 手紙のことを聞く | item_手紙 | | | | 1 | info_手紙の差出人 | | A_D3_対話_手紙 |
| A_D3_対話_1 | 2 | 黙って見つめる | | | | | -1 | | | A_D3_対話_沈黙 |
| A_D3_対話_1 | 3 | 話を変える | | | | | | | | |

- 手紙を持っていないときは「手紙のことを聞く」は出ず、2つだけ出る

## 5. セリフ（Excel）への SE・画像などの差し込み

### やりたいこと
Excel に書くセリフの中に、**SE を鳴らす指定** と **画像を差し替える指定** を書けるようにする。

### 決まっていること
- 今は SE と画像（立ち絵の差し替え）
- **将来的には、エフェクト（VFX・ポストエフェクトなど）、背景、イベント絵も** 指定できるようにしておく
- Excel でもっと簡単な書き方があればそれにする（なければ `[SE:名前]` `[IMG:名前]` の形でよい）

### 今の状態
セリフの中で使える指定は次の3つだけ（1つのセルに `|` で区切って書く）。
- `|`：ページ区切り
- `[SYS]`：話者名なしの地の文
- `[IMG:OFF]` / `[IMG:ON]`：立ち絵を消す / 戻す

### Excel の書き方（決定）: 「1行 = 1ページ」形式
1つのセルに `|` や `[SE:...]` を詰め込む代わりに、**1ページを1行** にして、SE や画像は **列** で指定します。

#### 例：同じ会話を2つの書き方で書いた場合
ココアに1日目に「対話」をしたときの会話（3ページ）。2ページ目で笑顔になり、3ページ目で SE を鳴らして立ち絵を消し、地の文を出したいとします。

**今の書き方（1つのセルに全部書く）**

| セリフ |
|---|
| `「……本についてですか？」\|[IMG:ココア_笑顔]「本は、人と違って裏切りません」\|[SYS][SE:風の音][IMG:OFF]彼女は窓の外を見つめた。` |

- ページの区切り（`|`）とタグ（`[SYS]` `[SE:…]` `[IMG:…]`）を覚えて、正しく書く必要がある
- 1つでも書き間違えると、タグの文字がそのまま画面に出る
- セルが長くなり、どこで何が起きるか読み取りにくい

**提案の書き方（1行 = 1ページ）**

| セリフID | 種類 | 本文 | SE | 立ち絵 | 背景 | イベント絵 | エフェクト |
|---|---|---|---|---|---|---|---|
| A_D1_対話_1 | 会話 | 「……本についてですか？」 | | | | | |
| A_D1_対話_1 | 会話 | 「本は、人と違って裏切りません」 | | ココア_笑顔 | | | |
| A_D1_対話_1 | 地の文 | 彼女は窓の外を見つめた。 | 風の音 | 非表示 | | | |

- **セリフID** が同じ行が1つの会話。上から順に1ページずつ表示される
- **種類**: 「会話」は話者名あり、「地の文」は話者名なし（今の `[SYS]` の代わり）
- **SE / 立ち絵 / 背景 / イベント絵 / エフェクト**: そのページを表示したときに切り替える。**空欄なら変更なし**（前のページのまま）
- 立ち絵の「非表示」で立ち絵を消す（今の `[IMG:OFF]` の代わり）

#### ゲーム内での見え方（どちらの書き方でも同じ）
| ページ | 話者名 | 表示される文 | 起きること |
|---|---|---|---|
| 1 | ココア | 「……本についてですか？」 | |
| 2 | ココア | 「本は、人と違って裏切りません」 | 立ち絵が笑顔に変わる |
| 3 | （なし） | 彼女は窓の外を見つめた。 | 「風の音」が鳴り、立ち絵が消える |

#### 比べると
- **よいところ**
  - タグの書き方を覚えなくてよい。空欄なら「変更なし」
  - 将来、背景やエフェクトを増やすときは **列を足すだけ**
  - Excel の入力規則（プルダウン）で SE 名や画像名を選べるので、打ち間違いが減る
- **気になるところ**: 行数が増える。今のセリフデータ（SO）と CSV 取り込みの仕組みを作り直す必要がある（Excel のセリフはまだ書いていないので、今が変えやすい）

### Excel のテンプレート
- ファイル: `Assets/Editor/ScenarioData.xlsx`（シート: 説明・本文・条件・日別設定・フラグ一覧・AI判定・エンディング・リスト）
- 取り込みは **1行目の見出しの名前** で列を探す。列の順番を入れ替えても、メモ用の列を足しても壊れない
- 1列目が `#` で始まる行は取り込まない（下書き・コメント用）
- 決めた5シートに加えて、今の作りを残すために次を足した
  - **日別設定シート**: 各日・各キャラの正解行動・NG行動（今のルール）
  - 条件シートの **聞き取り相手** 列: 「聞き取り」でだれについて聞いたときの会話か
  - 本文シートの **話者** 列（空欄なら会話の相手）と **BGM** 列（エンディングなどで使う）
  - エンディングシートの **一覧に表示する名前** 列（9番のエンディング一覧用）
- **スマホ会話（補助ちゃん）のセリフもこの Excel で書く**（今は Unity の Inspector で入力しているものを移す）
  - 条件シートの「行動」に **スマホ** を選び、キャラ欄は空欄、**回目** 列にその日の何回目の会話かを書く
  - その日に聞ける回数は、書いた「回目」の最大の数（例: 1 と 2 まで書けば、その日は2回）
  - 同じ回目に複数の行を書けば、取調室と同じく条件（フラグ・好感度など）で出し分けられる
  - 本文シートの「話者」に「補助ちゃん」と書く
- ※ まだゲームはこのファイルを読み込まない（取り込みの仕組みは4番目の作業で作る）

## 6. セリフの出し分け条件にキーアイテム・情報を追加

### やりたいこと
Excel で「どのセリフを出すか」を決める条件に、好感度以外に **キーアイテムや情報** も使えるようにする。

### 決まっていること
- 「キーアイテム○○を持っている」「情報○○を得ている」の条件を追加する
- **1つのセリフに複数の条件をまとめて付けられる**（例：キーアイテム2つ＋情報3つ＋好感度3以上、のすべてを満たしたときだけ出る）
- **「持っていない」「得ていない」という条件も入れる**（同じ情報・アイテム・フラグを何度も手に入れるのを防ぐため）

### 今の状態
今使える条件は次の4つで、1つのセリフに1つしか付けられない。
- 本人の好感度が○以上
- 他のキャラの好感度が○以上
- このキャラにこのアクションをした回数が○回以上
- 条件なし

### Excel の書き方（決定）: 条件を列に分けて、書いたものは全部「かつ」

Excel は **2つのシート** に分けます。
- **本文シート**: 会話の中身（5番の「1行 = 1ページ」の表）。セリフID ごとにまとまっている
- **条件シート**: 「何日目に、だれに、どの行動をしたとき、どのセリフID を出すか」と、その条件

#### 例：3日目にメリに「対話」をしたとき
メリへの対話で、次の3つの会話を出し分けたいとします。
- A: 証拠がそろっていて仲もいいときだけ話す「核心の話」
- B: レイジと仲がよく、まだアリバイを聞いていないときに話す「アリバイの話」（聞いたら `info_メリのアリバイ` が ON になる）
- C: それ以外の「いつもの話」

**条件シート**

| 日 | キャラ | 行動 | 優先度 | 本人の好感度 | 他キャラの好感度 | 行動回数 | 必要フラグ | NGフラグ | 獲得フラグ | セリフID |
|---|---|---|---|---|---|---|---|---|---|---|
| 3 | B | 対話 | 1 | 3 | | | item_鍵, item_手紙, info_ココアの証言, info_目撃, info_日記 | | | B_D3_対話_核心 |
| 3 | B | 対話 | 2 | | D>=2 | | | info_メリのアリバイ | info_メリのアリバイ | B_D3_対話_アリバイ |
| 3 | B | 対話 | 3 | | | | | | | B_D3_対話_いつも |

**本文シート**（5番の形式。条件シートのセリフID と対応する）

| セリフID | 種類 | 本文 | SE | 立ち絵 |
|---|---|---|---|---|
| B_D3_対話_核心 | 会話 | 「……そこまで調べたんですね」 | | メリ_真剣 |
| B_D3_対話_核心 | 会話 | 「全部話します」 | | |
| B_D3_対話_アリバイ | 会話 | 「あの夜は、ずっと取材先にいました」 | | |
| B_D3_対話_いつも | 会話 | 「今日も特に話すことはありません」 | | |

#### プレイヤーの状態ごとに、どのセリフが出るか
上の行（優先度1）から順に調べて、**書いてある条件をすべて満たした最初の行** のセリフが出ます。

| プレイヤーの状態 | 出るセリフ | 理由 |
|---|---|---|
| メリの好感度4、鍵・手紙・証言・目撃・日記をすべて持っている | B_D3_対話_核心 | 優先度1の条件（好感度3以上 かつ 必要フラグ5つ全部 ON）をすべて満たす |
| メリの好感度4、でも日記だけ持っていない | B_D3_対話_アリバイ または いつも | 必要フラグが1つ足りないので優先度1は不成立 → 優先度2以降を調べる |
| レイジの好感度2、メリのアリバイはまだ聞いていない | B_D3_対話_アリバイ | 優先度2の条件（D の好感度2以上 かつ `info_メリのアリバイ` が OFF）を満たす。聞き終わると `info_メリのアリバイ` が ON になる |
| 3日目にアリバイを聞いた後、4日目に対話した（4日目の条件シートにも同じ優先度2の行があるとする） | 4日目の「いつもの話」など | `info_メリのアリバイ` がすでに ON なので、NGフラグの条件で優先度2は不成立。同じ情報を2回もらわない |
| どれにも当てはまらない | B_D3_対話_いつも | 優先度3は条件が空欄＝いつでも成立 |

- **書き方のルール**
  - 書いた条件は **すべて満たしたとき（かつ）** だけ、そのセリフが出る。空欄は「条件なし」
  - 上の行（優先度が小さい）から順に調べて、最初に当てはまった行のセリフを出す（今と同じ）
  - **必要フラグ**: 書いたものが **全部 ON** のとき。カンマ区切りで何個でも書ける
  - **NGフラグ**: 書いたものが **全部 OFF** のとき（＝持っていない・得ていない）
  - **獲得フラグ**: そのセリフを聞いたら ON になる（3番の「特定のセリフで手に入る」に使う）
  - **他キャラの好感度**: `B>=2, C>=1` のように書く
  - **行動回数**: このキャラにこの行動をした通算回数が○回以上（今の「通算回数」の条件と同じ）
- **フラグの名前の付け方**: 先頭で種類が分かるようにする
  - `item_` キーアイテム（例：`item_鍵`）
  - `info_` 情報（例：`info_アリバイ`）
  - `flag_` それ以外の進行フラグ（例：`flag_ココアがAI`）
- **フラグ一覧のシート** を別に作る（名前・種類・説明・表示する文・プロフィールのどこに出すか）。取り込むときに、一覧にない名前があれば打ち間違いとして知らせる

| フラグ名 | 種類 | 説明 | プロフィールに表示する文 | 表示先 |
|---|---|---|---|---|
| info_メリのアリバイ | 情報 | 事件の夜のメリの居場所 | 事件の夜は取材先にいたと話した | B（メリのページ） |
| info_事件当日の天気 | 情報 | 事件当日の天気 | 事件当日は雨だった | その他 |
| item_鍵 | キーアイテム | 現場の部屋の鍵 | 現場の部屋の鍵。だれかが持ち出していた | アイテム |
| flag_ココアと和解 | 進行フラグ | AI化を防ぐ条件などに使う | （表示しない） | なし |

## 7. AI になるキャラをフラグで変える

### やりたいこと
今は AI がココアに固定されているが、プレイの進め方によって AI になるキャラが変わるようにする。
- Excel の特定のセリフを見たとき、または **特定の日までに特定のフラグを達成できなかった場合**、そのキャラが AI になる
- 逆に、**特定のフラグを達成したら AI にならない**

### 決まっていること
- **ゲーム開始時は全員人間**（今のように最初から AI のキャラはいない）
- AI になるキャラは **複数人になることも、0人になることもある**
- **AI が決まるタイミングは2種類**
  - 条件を満たした **瞬間**（例：特定のセリフを見た）
  - **決まった日** に判定（例：○日目までに特定のフラグを達成しなかった＝特に何もしなかった場合）
- 一度 AI になったキャラが元に戻ることは **今のところない**
- **最終日の判定**
  - **AI確定ボタン** と **解放ボタン** は、どちらも **最終日にだけ** 表示する
  - プレイヤーは、AI だと思う人を「AI確定」し、AI ではないと思う人を「解放」する
  - AI が複数人いる場合は、**全員を AI確定** する必要がある
  - AI が0人の場合は、**全員を解放** することで「AI はいない」と判定する
  - 最終日の取調室では、**拷問・対話・交渉・聞き取りの4つのボタンは非表示**にして押せないようにする（最終日は取り調べできない）
  - 最終日の「解放」と「AI確定」は、どちらも **行動回数を1回使う**（4人を1回ずつ判定するので回数が足りなくなることはない）
  - 判定が終わったら、今ある **「1日を終える」ボタン** を押して終了する（リザルト → エンディングへ）
  - **判定していない人が残っている場合は、「1日を終える」を押しても終了できない**。そのときは **「まだ判定していない人がいます」** などの文を出して知らせる
  - 一度判定した人の部屋には入れない（判定のやり直しは「今日をやり直す」で行う）
- **勝ち負け・エンディング**
  - **AI を1人でも解放したらゲームオーバー**（今のルールのまま）
  - 人間を間違って AI確定しても、それだけではゲームオーバーにならない（AI を見つけるゲームなので）
  - ただし、間違いの有無などで **エンディングを分岐させる予定**

### 今のルールから変わること
- 今は **解放が1〜7日目のいつでもできる**（行動1回を使う）が、**最終日だけ** になる
- 今は **AI確定は1人だけ** 選べて、選んだ時点でリザルトへ進むが、**複数人を AI確定** できるようになり、終了は「1日を終える」ボタンで行う
- 今は最終日も取り調べができるが、**最終日は判定（AI確定・解放）だけ** になる
- 今は AI が最初から決まっている（ココア）が、**フラグで途中から AI になる** ようになる

### 未定
- 具体的な条件（どのキャラが、どのフラグで、何日目までに AI になる・ならないか）
- エンディングの種類と分岐条件
- 「まだ判定していない人がいます」の正確な文言（決まるまではこの文で仮置き）

### AI になる条件の Excel の書き方（決定）
AI になる仕組みは2つあります。

#### ① セリフを聞いたら AI になる（条件シートの「AI化」列）
6番の条件シートに **「AI化」列** を足します。その行のセリフを聞いたら、書いたキャラが AI になります。
- **本人でも、他のキャラでもよい**（例：ココアとの会話で、レイジが AI になる）
- 複数人も書ける（例：`B, D`）
- 空欄なら、だれも AI にならない

| 日 | キャラ | 行動 | 優先度 | 本人の好感度 | 必要フラグ | NGフラグ | 獲得フラグ | AI化 | セリフID |
|---|---|---|---|---|---|---|---|---|---|
| 4 | A | 拷問 | 1 | | | flag_ココアと和解 | | A | A_D4_拷問_暴走 |
| 4 | A | 対話 | 1 | 2 | info_レイジの嘘 | | | D | A_D4_対話_告発 |

- 1行目: 4日目にココアを拷問したとき、まだ和解していなければ、ココア本人が AI になる
- 2行目: 4日目にココアと対話したとき、好感度2以上でレイジの嘘を知っていれば、**レイジ（他のキャラ）が AI になる**

#### ② 決まった日までに進展がなければ AI になる（AI判定シート）
条件シートとは別に **「AI判定シート」** を作ります。
**判定日の終わり**（「1日を終える」→ 翌日になるとき）に、**回避フラグがすべて ON になっていなければ** そのキャラが AI になります。

| キャラ | 判定日 | 回避フラグ | メモ |
|---|---|---|---|
| A | 3 | flag_ココアと和解 | 3日目までにココアと和解できなければ AI になる |
| C | 5 | info_カネルの過去, item_手紙 | 5日目までに過去を知り、手紙も見つけていなければ AI になる |

- 回避フラグはカンマ区切りで何個でも書ける（すべて ON で回避）
- 何も行動しなくても日数が過ぎれば判定される（「特に何も進展しなかった場合」に AI になる）

#### 共通のルール
- 一度 AI になったら、元には戻らない（ただし「今日をやり直す」をすれば、その日に AI になった分は朝の状態に戻る）
- **①と②は別々に判定する**。②の回避フラグを達成していても、①の AI化列のセリフを聞けば AI になる。①で AI にさせたくない場合は、①の行に NGフラグを書いて防ぐ（上の例の1行目の `flag_ココアと和解` がこの使い方）
- **（AI の解釈）** だれが AI になったかは、プレイヤーには見えない（推理して最終日に判定する）

## 8. セーブ・ロード

### やりたいこと
7日間の途中でゲームをやめても、続きから遊べるようにする。

### 決まっていること
- **手動セーブ**（自動セーブはしない）。**セーブボタンは必須**
- セーブ枠は **20枠くらい**
- タイトル画面は「はじめから」「つづきから」「エンディング一覧」「オプション」の4つ
- **セーブボタンはゲーム中のオプション画面** に置く
- **ロードはタイトル画面（つづきから）とゲーム中（オプション画面）の両方** でできる
- 使用中の枠への上書き・セーブの削除・ゲーム中のロードの前には **確認を出す**
- クリア・ゲームオーバーになったら、**そのセーブを消すかどうかをプレイヤーが選べる**
- 音量など **オプションの設定はセーブとは別に保存** する（1番で決定済み。どのセーブでも共通）

### （提案）作り方
- 手動セーブなので、**日の途中の状態** を保存する。保存する内容: 日数、ポイント、好感度、フラグ、AI の状態、行動回数、取り調べ済みの記録、行動の通算回数、プロフィールの解禁状態、スマホの会話回数、ログ、既読の記録（15番）
- **その日の朝の状態も一緒に保存** する（ロードした後でも「今日をやり直す」で朝に戻れるようにするため）
- 会話の途中（セリフ表示中・選択肢を選んでいる途中）はセーブできない。会話が終わった状態で保存する
- 各セーブ枠には「何日目か」「保存した日時」「残り行動回数」を表示する
- タイトル画面から開いたオプションには、セーブ・ロードのボタンは出さない（ロードは「つづきから」で行う）

## 9. エンディングの分岐

### やりたいこと
最終日の判定の結果やフラグによって、エンディングを分岐させる（7番の続き）。

### 決まっていること
- AI を1人でも解放したらゲームオーバー
- 人間を間違えて AI確定しても、それだけではゲームオーバーにならない
- エンディングを分岐させる。**ゲームオーバーもエンディングの1つとして同じ仕組みで扱う**
- エンディングは **会話の形（本文シートの文章とイベント絵）で見せた後**、今の **クリア画面・ゲームオーバー画面（それぞれ別のシーン）** に移る
- 見たエンディングを記録して、**エンディング一覧** を見られるようにする
  - **タイトル画面** から見る
  - まだ見ていないエンディングは **「？？？」のように隠して、数だけ分かる** ようにする
  - 見たエンディングは、一覧から **もう一度再生** できる
  - エンディング一覧の記録は、セーブ枠とは別に保存する（どのセーブで見ても記録される）

### Excel の書き方（決定）: 「エンディングシート」

| 優先度 | 判定結果 | 必要フラグ | NGフラグ | 種類 | エンディングID |
|---|---|---|---|---|---|
| 1 | AIを解放した | | | ゲームオーバー | END_ゲームオーバー |
| 2 | 全員正解 | flag_ココアと和解 | | クリア | END_真エンド |
| 3 | 全員正解 | | | クリア | END_通常クリア |
| 4 | 人間をAI確定した | | | クリア | END_冤罪 |

- **判定結果** の種類: 「全員正解」「人間をAI確定した」「AIを解放した」「指定なし」
- **種類**: 会話の後に「クリア画面」と「ゲームオーバー画面」のどちらに移るか
- エンディングの中身は5番の本文シートと同じ形（1行 = 1ページ）で書き、背景・イベント絵・BGM も指定できる

## 15. 文字送りの速さ・オート・スキップ

### やりたいこと

- スキップの2種類は、**オプションで「既読のみ／すべて」を切り替える**
- オートの待ち時間は **3段階（短い・普通・長い）**

## 17. 初めてでも操作が分かる画面
